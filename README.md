# AI 网页翻译助手

> 任何网页，只要不是简体中文就自动翻成中文；F9 随时重译。三层路径依次接力：**本地界面词条 → AI 大模型 → 免费引擎链**，前一层能解决就不花后一层的钱。

用户脚本，装一个脚本管理器（篡改猴、脚本猫、暴力猴等）即可 · 当前版本 **1.4.19** · [安装](#安装) · [国内网络与 GitHub 访问](#国内网络与-github-访问)

## 功能

- **整页翻译**：所有站点同一条流程 —— 界面词条命中即替换，剩余文本交给配置好的大模型批量翻译；AI 未启用、没填 Key、请求失败，或文本超出 AI 处理范围（单条 >600 字符或 >150 词）的那部分，才回退到 Bing → MyMemory → Google 引擎链。非简体中文网页会自动触发这一整套流程，按 F9 也能随时重译。
- **界面词条**：内置常见界面文案 + 数量/时间模式规则 + CSS 规则，远端词条库每天从仓库同步，覆盖导航、按钮、属性、相对时间、占位符等，自动排除代码块、文件名、路径。**所有网站共用同一套词库，不按站点区分**——词条以 GitHub 界面用词为主，但保存、设置、成员、部署、上次修改这类通用界面词在任何网页都会命中。具体条数见 [词库规模](#词库规模自动更新)，生效范围见 [界面词条的覆盖范围](#界面词条的覆盖范围)。
- **免费引擎链**：Bing 鉴权失败自动刷新重试，上次成功的引擎优先，长文本自动分段。不填任何 Key 也能用。
- **AI 翻译**：默认开启。待译文本按批（默认 20 条/批）交给大模型，译文写入缓存，二次访问同一句直接命中、零请求。提示词带页面标题与站点上下文，按「中文网站原生文案」标准翻译：界面短词保持简短、句子译得通顺、杜绝翻译腔。
- **词条在线更新**：词条库正式版托管在 GitHub 仓库，每天北京时间 0 点后首次访问自动同步一次；GitHub 原始地址与 gh-proxy 反代并发、谁先到用谁，失败再依次换 jsDelivr 两个域名。详见 [界面词条库](#界面词条库)。
- **译文缓存**：AI 与引擎译文都落在本机存储，避免重复请求。
- **词条回传**：翻译时顺手采集「词条库没命中、靠 AI 翻出」的界面短句，攒够后一键回传仓库；没有 Token 也能提交，详见 [词条回传](#词条回传)。

## 数据与隐私

先把会联网的部分说清楚，免得装完才发现：

| 动作     | 发出去的内容               | 发给谁                              | 什么时候                 |
| ------ | -------------------- | -------------------------------- | -------------------- |
| AI 翻译  | 页面待译文本（按批，附页面标题作上下文） | 你在设置里填的 AI 服务商                   | 自动翻译触发，或按 F9         |
| 免费引擎兜底 | 页面待译文本               | Bing / MyMemory / Google         | AI 未启用、失败或文本超长时      |
| 词库同步   | 无（只读 GET，不上传任何内容）    | GitHub raw / gh-proxy / jsDelivr | 每天 0 点后首次访问，或点「立即更新」 |
| 词条回传   | 你手动确认的词条清单           | 本仓库 `dict/contribs/` 或 Issue     | **默认关闭**，必须手动点按钮     |

- **不收集**用户身份、Cookie、浏览历史；没有统计、埋点、上报接口。
- **API Key** 只存本机脚本管理器存储，公开版内置 Key 为空；换管理器要重填一次。
- **词库是纯数据**：JSON 里的 24 条正则和 1 条 HTML 替换规则只用于文本替换，不是可执行代码，且来自同一个公开仓库。
- **想少发请求**：设置里关掉「非简体中文页面自动翻译」，就只有按 F9 才会发起翻译请求。AI 也能单独关闭，但关掉后 F9 仍会走免费引擎链、页面文本照样外发。介意页面内容离开本机的话，请不要安装。

**完整对外域名**（与脚本头 `@connect` 一致，未列出的域名不会发起请求）：

| 用途                  | 域名                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 免费翻译引擎              | `cn.bing.com`、`www.bing.com`、`translate.googleapis.com`、`api.mymemory.translated.net`                                                             |
| AI 服务商（只连设置里选定的那一个） | `integrate.api.nvidia.com`、`api.deepseek.com`、`api.openai.com`、`dashscope.aliyuncs.com`、`open.bigmodel.cn`、`api.moonshot.cn`、`api.siliconflow.cn` |

## 触发方式

**自动（默认开启）**

- 页面就绪后自动检测页面主语言：只要**不是简体中文**就翻译成简体中文。英文、日文、韩文、德文、法文、俄文一视同仁；繁体中文会转成简体。
- 检测顺序：先看 `html[lang]` 声明，再用字符统计兜底 —— 出现假名判为日文，出现韩文判为韩文，汉字占比 ≥ 25% 判为中文，其余视为其它语种；判为中文后再用繁体特征字区分简繁。
- 文字总量不足 250 的页面（代码页、图片页、纯符号页）不自动翻。
- 最多探测 3 轮（间隔 1.2 秒），照顾前端渲染慢的站点；每次页面加载只自动执行 1 次，不会反复翻。
- 设置面板里「非简体中文页面自动翻译」可以关掉，关掉后只剩 F9。

**手动 F9**

- 页面尚未翻译时：按 F9 直接翻译。
- 页面已经翻译过：再按 F9 会**先恢复原文，然后按当前设置重新翻译**（绕过 AI 缓存与译文缓存，改完模型 / Key 后不用刷新页面即可重译）。
- 焦点在输入框或可编辑区时按 F9 不触发，避免打断打字。
- 连按 / 长按 F9 只执行一次，不重复翻译。

**关闭翻译**

- 篡改猴菜单 → **关闭翻译（恢复原文）**：把本页所有已翻译的节点恢复为原文，提示恢复了多少处；随后按 F9 可随时重新翻译。
- 没有已翻译内容时会提示「当前页面没有已翻译的内容」；某轮翻译还在进行中时会提示先等本轮结束。
- 设置面板底部也有 **恢复原文** 按钮，效果相同，改完设置顺手就能还原。

**打开设置面板**

- 默认快捷键 **Alt+N**，可在面板「参数 → 设置快捷键」里改成 `Ctrl+Shift+K` 这类组合（只支持 Ctrl / Alt / Shift + 单个字母、数字或 F1–F12）。
- **Ctrl+N 用不了**：它是浏览器「新建窗口」的保留快捷键，网页脚本拦不住（同理还有 Ctrl+T / Ctrl+W / Ctrl+Shift+N）。真要改，填了也不会生效，脚本会在这种情况下直接忽略。

## 三层路径与优先级

按 F9 之后的处理顺序：

1. **界面词条**（所有站点）：内置词条 + 远端同步的词条，命中就直接替换，不花 AI 额度。
2. **AI 大模型**（所有站点，默认路径）：剩下的英文按批送大模型翻译，命中缓存的直接复用。
3. **引擎链**（兜底）：只有 AI 不可用、请求失败、或文本超出 AI 处理范围时才走 Bing → MyMemory → Google。

关闭 AI 或没填 Key 时，第 2 步自动跳过，全部落到第 3 步。

## 界面词条的覆盖范围

结论先说：**覆盖常规界面文本（按钮、导航、表单项、相对时间这类），所有网站共用同一套词库，但不等于「页面里每一个字都会变中文」**。下面是逐项核对的结果。

### 已覆盖

| 位置         | 实现方式                                                                                                        | 备注                  |
| ---------- | ----------------------------------------------------------------------------------------------------------- | ------------------- |
| 普通文本节点     | `TreeWalker` 遍历 `body`，长度 2–2000 字符，单次上限 2500 个节点                                                           | 先整句精确匹配，再按词拆分       |
| UI 短文本     | 父元素为 `A` / `BUTTON` / `LI` / `NAV` / `HEADER` / `OPTION` / `SELECT`，且不超过 6 个词                               | 拆词拼译，提高命中率          |
| 数量 + 单位    | 24 条模式规则，例如 `3 commits` → `3 个提交`、`2 hours ago` → `2 小时前`                                                   | 远端词库还可追加规则          |
| 表单按钮       | `input[type=button/submit/reset/image]` 的 `value`                                                           |                     |
| 占位符        | `input` / `textarea` / `select` 的 `placeholder`                                                             |                     |
| 无障碍标签      | `aria-label`                                                                                                |                     |
| 相对时间       | `<relative-time>`、`<time[datetime]>`、`[data-view-component][datetime]`，用 `Intl.RelativeTimeFormat('zh-CN')` | 含 Shadow DOM 内的相对时间 |
| 指定元素       | `CSS_RULES`（如 PR 页的 `a[aria-label='Pull requests you created']`）                                            | 目前 1 条              |
| 词库未命中的英文短句 | 交给 AI 批量翻译（F9 / 自动翻译时）                                                                                      | 失败再走引擎链             |

### 不覆盖（按设计排除）

> 下表里用类名的规则（`.markdown-body`、`.blob-code` 等）来自 GitHub，在别的网站自然不匹配，不会误伤；真正跨站点生效的是标签级排除（`code` / `pre` / `svg` / 跨域 iframe 等）。

| 范围                                                                                               | 原因                                           |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| `code` / `pre` / `kbd` / `samp` / `var` / `tt` / `data`，以及任何祖先含 `code`/`pre` 的元素                 | 代码、命令、diff 内容不能翻，翻了就打不开                      |
| `.markdown-body`（README、Issue/PR 正文、评论正文）                                                        | 正文是阅读对象，翻译会破坏链接、表格、代码块；只在缺失时由 AI 兜底普通文本，不含正文 |
| `.blob-code` / `.cm-editor` / `.CodeMirror` / `.diff-table` / `.diff-view` / `.react-code-lines` | 代码查看器与 diff                                  |
| `.js-navigation-container` / `.react-tree-show-tree-items` / `.js-path-segment` / `.final-path`  | 文件树与路径，翻了会指错文件                               |
| `.table-list` / `.pagination` / `.diffstat` / `.topic-tag` / `.Label` / `.float-right`           | 数值与状态标签，误译代价高（`Label` 本身还是组件类名）              |
| `itemprop="name"` 的元素                                                                            | 仓库名、Issue/PR 标题等标识性文本，保持原样便于搜索和复制            |
| `svg` / `math` / `iframe` / `object` / `template` / `noscript` / `script` / `style`              | 非可视文本或跨文档                                    |
| Shadow DOM 内部（相对时间除外）                                                                            | `TreeWalker` 不进入 shadow root                 |
| 跨域 iframe 内的文档                                                                                   | 浏览器同源策略                                      |
| `title` 属性（悬停提示）、`img` 的 `alt`                                                                   | 目前只处理 `aria-label` 与 `placeholder`           |
| CSS 伪元素 `content`、`canvas`、图片里的文字                                                                | 不是 DOM 文本节点，脚本无法改写                           |
| 浏览器标签页标题 `<title>`                                                                               | 未处理，避免影响收藏与历史记录                              |

### 结构性限制

1. **只处理 F9 那一刻的 DOM**：脚本没有 MutationObserver，SPA 之后渲染出来的新内容不会自动变中文；再按一次 F9 会恢复原文后整页重译。
2. **长文本会被跳过**：单个文本节点超过 2000 字符不处理；AI 单条超过 600 字符或 150 词也不处理，交给引擎链。
3. **单次节点上限 2500**：Issue 列表、大 diff 这类超长页面，尾部内容可能这一轮没翻到，再按 F9 可继续。
4. **词库是精确匹配**：按「小写 + 空白归一」的原文匹配，带变量插值的句子只能靠模式规则或 AI，不会因为词库里没有就瞎猜。
5. **通用站点可能出现词条误伤**：词条匹配的是整段文本，正文里单独出现的 `watch`、`build`、`search` 这类词会被换成界面译法。词条以界面短文案为主（不超过 160 字符），长句不进词库，所以影响面有限；具体页面翻得不对，按 F9 恢复原文即可。

## 界面词条库

### 存放位置

词条库（下文简称「词库」）的正式版本放在本仓库：

```text
dict/zh-CN.json
```

脚本内置的 1656 条只是**离线兜底**；只要网络正常，启动后会套用仓库里更新过的版本（当前 2330 条，与内置同名的是覆盖，合计 2333 条）。

### 面板里的数字怎么算

设置面板「界面词条」会同时出现几个数字，它们不是同一个口径，容易看着像「多出来一截」：

| 显示         | 含义                                                  |
| ---------- | --------------------------------------------------- |
| 内置 1656 条  | 脚本自带的离线兜底词条。`__comments-*`、`__dict-end` 之类的注释占位键不计数 |
| 远端新增 677 条 | 仓库词库 2330 条里与内置**不重名**的部分；重名的 1653 条是覆盖内置，不累加       |
| 词库 2333 条  | 1656 + 677，实际参与匹配的总条数                               |
| AI 记忆 N 条  | AI 翻过的句子会被记住以便复用（存本机），属于译文缓存，**不是词库**，不计入上面任何数字     |

AI 记忆随使用不断增长（按 F9 重译也会更新它），但它始终不进词库本体；清掉本机缓存后归零，不影响词库条数。统计口径可跑 `node tools/dict_stat.js` 核对。

### 自动化工作流

仓库有 5 条工作流，分工如下：

| 工作流             | 什么时候跑                                                                 | 干什么                                                                                                                                | 能不能改文件            |
| --------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| **词库质量检查**      | 每次往 `dict/`、`tools/`、工作流目录推代码，或提 PR                                   | 跑 `tools/dict_lint.js`：键格式（大小写/首尾空格/连续空格）、重复键、空译文、`count` 字段一致性、术语统一（如 workflow 必须译作「工作流」）、`patterns` 正则能否编译；结果写进 Job Summary，有错就红 | 否（只读）             |
| **词库自动续写**      | 每天北京时间 12:00                                                          | 从 `tools/candidates.txt` 里挑词库还没有的界面短语，交给 AI 翻译后补进 `dict/zh-CN.json`；写入后先跑一遍质量检查，不过就回滚不提交                                           | 是（只改词库）           |
| **词库 Issue 接收** | 自己人（OWNER/MEMBER/COLLABORATOR）开的 Issue 自动；其他人开的需要你打「词库贡献」标签；也可手动填编号触发 | 解析 Issue 正文里的 `原文 → 译文`，存成 `dict/contribs/contrib-issue-<编号>.json`，回帖说明收了几条                                                        | 是（只加贡献文件）         |
| **词库贡献合并**      | 每天北京时间 12:20，或你手动点 Run workflow                                       | 把 `dict/contribs/*.json` 合并进正式词库（只加不改；定时任务永不覆盖），合并后跑质量检查，通过才提交并清理贡献文件、同步 README 数字，版本号 `-rN` +1                                    | 是（改正式词库 + README） |
| **词库统计**        | 每天北京时间 12:40，或 `dict/` 变动时                                            | 生成总数 / 与内置的重叠 / 键长分布等统计，写 Job Summary，并把上面那张「词库规模」表更新进 README                                                                      | 是（只改 README 那个区块） |

每天的固定顺序是 **12:00 续写 → 12:20 合并贡献 → 12:40 统计**。统计放在最后，测的就是当天续写和合并之后的最终规模；三条依次错开 20 分钟，不会抢同一条提交。

人工闸门只剩一道，但它守在最前面：**打标**决定这条 Issue 要不要进队列（有仓库写权限的用户自己能推 `dict/contribs/`，本身就等于已授权）。进了队列之后就由 12:20 的定时任务自动合并——定时任务固定只加不改，合并后还必须过词库检查，不过就放弃提交。想覆盖已有条目（改错译）只能在手动触发时勾 force。AI 续写虽然全自动，也有「写完先自检、不过就回滚」的保险。

### 文件结构

```json
{
  "schema": 1,
  "version": "2026.11.08-r2",
  "count": 2330,
  "dict": { "watch": "关注", "fork": "复刻" },
  "patterns": [{ "re": "^([\\d,.]+)\\s+commits?$", "to": "$1 个提交" }],
  "cssRules": [{ "key": "!html", "selector": "a[aria-label='...']", "replacement": "拉取请求" }]
}
```

- `dict`：键为「小写 + 空格归一」的英文原文，值为简体中文。
- `patterns`：正则规则，处理词库难穷举的「数量 + 单位」和相对时间。
- `cssRules`：需要按元素选择器改属性或整段文本的特殊情况。

### 每天自动同步

- **时机**：每天**北京时间 0 点之后**首次打开任意页面时同步一次，24 小时内最多一次。
- **为什么不是 0:00 准点**：浏览器会给后台标签页的定时器降频甚至冻结，脚本里挂一个「等到 0 点」的定时器并不可靠，而且页面没打开时脚本根本不在运行。所以采用「跨日首次访问即拉取」的等价实现。
- **换源策略**：前两个源**同时发**，谁先返回有效词库用谁；只有它们都失败，才依次往下试。
  | 顺序 | 源                                        | 说明             |
  | -- | ---------------------------------------- | -------------- |
  | 1  | `raw.githubusercontent.com`（GitHub 原始地址） | 海外快，国内常不通      |
  | 2  | `gh-proxy.com`（raw 反代）                   | 国内可直连，与第 1 个并发 |
  | 3  | `testingcf.jsdelivr.net`                 | 前两个都失败才轮到      |
  | 4  | `cdn.jsdelivr.net`                       | 最后兜底           |
  单个源超时 8 秒；前两个并发，所以最坏情况约 8 + 24 秒，全程在后台跑，不阻塞首屏，也不打断正在进行的翻译。
- **校验**：响应必须是以 `{` 开头的合法 JSON，且 `dict` 条目数 ≥ 100 —— 这一步专门挡掉反代返回的 HTML 错误页。
- **失败处理**：全部源都失败时保留上一次的词库继续用，不会清空、不会报错弹窗，下一天再试。
- **缓存**：合格的响应写入本机存储（`ghx2_dict_remote` / `ghx2_dict_meta`），断网时照样用上次同步的内容。

### 手动更新

两个入口，效果相同（强制忽略「今天已同步」）：

- 篡改猴菜单 → **立即更新词库**
- 设置面板 → 界面词条 → **立即更新**（面板里同时显示当前版本、条目数、来源、上次同步时间）

### 词条回传

词条库是社区一起长的，所以面板底部有一个可折叠的 **词条回传** 区块：

| 步骤         | 说明                                                                   |
| ---------- | -------------------------------------------------------------------- |
| 1. 开启采集    | 打开「采集未命中词条」开关并保存。之后词库没命中、靠 AI 或引擎翻出的**短文案**（≤80 字符、单行）会记在本机，最多 500 条 |
| 2. 查看 / 复制 | 面板显示已采集条数；「复制清单」复制成 `原文 → 译文` 的纯文本                                   |
| 3. 回传      | 有 Token 走「推送到 GitHub」；没 Token 走「提交 Issue」                            |

两种回传方式：

- **有 Token（推荐自己用）**：在「词条回传」里填一个带仓库写权限的 GitHub Token（只存本机，不随词库上传）。两个按钮任选：
  - 「推送到 GitHub」——把清单写成 `dict/contribs/contrib-<日期>-<时间>.json` 直接提交到 `main`，成功后本地清单清空；
  - 「提交 Issue」——用 API 直接建单，正文不受 URL 长度限制，一次能提满 300 条上限。脚本会先查这个 Token 对仓库有没有写权限：**有**就顺带打上「词库贡献」标签（Issues 列表可筛，和人工打标同一口径）；**没有**（只读 Token）就不带标签，避免 GitHub 退回。连点有 60 秒冷却，防止刷出一串重复 Issue。
- **没有 Token（其他用户）**：点「提交 Issue」，脚本生成一条预填好的 Issue（正文最多 300 条，按 URL 长度自动收敛，可分批续点）。你给它打上「词库贡献」标签后，**「词库 Issue 接收」工作流**把它解析成 `dict/contribs/contrib-issue-<编号>.json` 进入同一条合并队列并回帖告知条数；接下来就等每天 12:20 的自动合并。

维护者自己（OWNER / MEMBER / COLLABORATOR）开的 Issue 是例外：作者即审核人，工作流看到 `author_association` 是这三个之一就直接解析，不必再打标。

为什么不让人直接写正式词库：去重、术语一致性、错译纠正都需要过眼，任何一条错的都会推给所有用户。所以贡献先进 `dict/contribs/` 队列（Issue 需打标才入队，推文件需仓库写权限），再交给定时任务批量合并——这样无 Token 的用户也有零门槛通道，不需要注册什么服务、也不需要脚本作者提供服务器。


### 合并规则

1. 远端条目**覆盖**同名内置条目 —— 修错译、统一术语靠这条路。
2. 远端条目同时写入词库基线，所以 F9「再次翻译」清理 AI 译文时不会误删它们。
3. `patterns` 与 `cssRules` 去重后追加，重复同步不会越叠越多。
4. 空译文会被丢弃（旧版词库里有 2 条空值，会把对应英文整段抹成空白）。

## 国内网络与 GitHub 访问

国内网络下 `github.com` 与 `api.github.com` 经常不通，脚本按「读」和「写」分别处理：

**读（同步词库）** 走 4 个源，前两个**同时发、谁先返回有效词库用谁**——GitHub 原始地址（海外快）与 `gh-proxy.com` 反代（国内快），谁也不等谁超时：

| 顺序 | 源                           | 说明                   |
| -- | --------------------------- | -------------------- |
| 1  | `raw.githubusercontent.com` | 官方原始地址               |
| 2  | `gh-proxy.com` 反代           | 国内可直连，实测约 1 秒        |
| 3  | `testingcf.jsdelivr.net`    | jsDelivr，前两个都失败才轮到这里 |
| 4  | `cdn.jsdelivr.net`          | jsDelivr 备用域名        |

**写（回传词库）** 走 GitHub API，直连不通时自动换镜像：

- 默认策略：先试 `api.github.com`（6 秒超时），**只有网络层失败**（被墙、超时、断网）才换 `https://gh-proxy.com/https://api.github.com`；GitHub 真的回了 401/403 就原样报错，不会把同一个写请求发两遍。
- 面板「词条回传」里可以填自己的镜像地址，或打开 **只走镜像**（连直连都不试），适合 `api.github.com` 完全不可达的情况。
- ⚠️ **走镜像时 Token 会经过第三方服务器**。请用**细粒度 Token**，只勾这一个仓库的 `Contents` 与 `Issues` 写权限，泄露也能一键撤销；介意就把镜像填成自己搭的地址。

**没有 Token 的用户**：`github.com` 的 Issue 页面在国内通常打不开，所以点「提交 Issue」时脚本会**先把整段正文复制到剪贴板**，再尝试打开网页。网页开不了也没关系——把剪贴板里那段直接发给维护者（QQ、微信、邮箱都行），格式已经是标准的 `- 原文 → 译文`，直接能解析。

维护者合并用户贡献，两种方式任选：

**方式一：交给定时任务（默认，不用管）**

每天北京时间 **12:20** 自动跑一次「词库贡献合并」，流程固定：

1. 队列为空 → 直接结束，不会产生空提交；
2. 有内容 → 合并进正式词库（**只加不改**，定时任务不接受 `--force`）；
3. 合并后跑词库检查，不通过就 `git checkout` 回滚、不提交；
4. 通过则连同 README 统计数字一起提交到 `main`，并清理已合并的贡献文件，版本号 `-rN` +1；
5. 全部用户在每天北京时间 0 点后自动拿到新词库。

需要覆盖同名条目（改错译）时，改用手动触发：Actions → 「词库贡献合并」→ Run workflow → force 填 `true`。

**方式二：本地命令行**

```bash
git clone 本仓库 && cd AI-Web-Translation-Assistant
node tools/merge_contrib.js --dry     # 先看统计：新增/跳过/覆盖各多少
node tools/merge_contrib.js           # 正式合并，自动清理已合并文件、version -rN +1
node tools/merge_contrib.js --force   # 需要覆盖同名条目时用（改错译）
# 确认无误后提交 dict/zh-CN.json 并推送
```

> Issue 渠道的自动化（**打标才解析**）：用户提交 Issue 后不会立刻处理，维护者确认要收这条时给它打上「词库贡献」标签，`.github/workflows/dict-issue-intake.yml` 才会跑 `tools/issue_to_contrib.js` 解析正文——  
> 这样任何人开 Issue 都不会自动往仓库写文件；也可以在 Actions 页手动触发并填写 Issue 编号。解析规则：  
> 只认 `- 原文 → 译文` 单行；单条 Issue 上限 300 条、键与译文各 200 字符；含 HTML 标签、URL、代码块、以及中文→外文的反向条目一律跳过；解析结果写进 `dict/contribs/`，然后在 Issue 里回帖说明接收了几条、跳过几行。  
> 解析失败或没有可用词条时不会提交任何文件，只在 Issue 里说明，维护者仍可人工处理。

## AI 大模型设置

打开设置入口：最省事是直接按 `Alt+N`；也可以从脚本管理器的菜单进——篡改猴/暴力猴是**扩展图标 → 本脚本 → 「AI 翻译设置」**，脚本猫是**面板 → 脚本 → 菜单**。

设置只放在这一处，脚本不会往网页里注入任何按钮或悬浮元素——脚本覆盖所有站点，常驻按钮会在每个网站挡住页面左下角的内容。

面板是一个居中的设置卡片，按分区排布：运行方式（开关）、接口、参数、界面词条、词条回传。关闭方式有三种：右上角 ×、按 `Esc`、点击卡片外的遮罩。API Key 默认打码，点右侧「显示」可临时查看。

面板里可填：

| 字段            | 说明                                              |
| ------------- | ----------------------------------------------- |
| 启用 AI 翻译      | 默认开启。关闭后完全不请求大模型，全部走引擎链                         |
| 非简体中文页面自动翻译   | 默认开启。自动检测语种，非简体中文即翻译；关闭后只由 F9 触发                |
| 接口类型 provider | `nvidia` / `openai` / `builtin`（浏览器内置 AI，免 Key） |
| 接口地址 baseUrl  | OpenAI 兼容的 `/chat/completions` 地址               |
| API Key       | 大模型 Key，仅保存在本机                                  |
| 模型名称 model    | 例如 `nvidia/nemotron-3.5-super-vl-120b-a12b`     |
| 批量条数          | 每次请求翻译多少条                                       |
| 每条最长字符        | 默认 600；超过的不交给 AI，走引擎链                           |
| 超时            | 请求超时毫秒                                          |
| 推理模型关闭思考      | NVIDIA Nemotron 系列需要                            |
| 译文写入缓存        | 关闭则不缓存                                          |

「界面词条」分区显示当前词条库版本、条目数、来源和上次同步时间，右侧「立即更新」可手动拉取（见 [界面词条库](#界面词条库)）。

填完点 **保存**；点 **测试连接** 会用当前值发一次真实请求验证可用性。配置存在脚本管理器的存储里，重启浏览器后仍在。

> 公开版本内置的 NVIDIA API Key 已置空，使用前请在设置里填入你自己的 Key；或 provider 选 `builtin` 用浏览器内置 AI（免 Key）。
