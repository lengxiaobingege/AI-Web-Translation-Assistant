# 上架 Greasy Fork

维护者操作手册。发布渠道由脚本猫站改为 Greasy Fork；`docs/脚本猫上架.md` 已废弃删除。

审查依据（均为官方页面，2026-11-09 核对）：

- [脚本规则](https://greasyfork.org/zh-CN/help/code-rules)
- [外部脚本规定](https://greasyfork.org/zh-CN/help/external-scripts)
- [`@antifeature` 类型](https://greasyfork.org/zh-CN/help/antifeatures)
- [发布时的元数据改写](https://greasyfork.org/zh-CN/help/rewriting)

**换渠道的三个实际好处**

1. 官方明文写「加载但非可执行代码不受限制，例如 JSON 或 CSS」——我们的远端词库是纯 JSON，规则边界清楚，不用像脚本猫那样靠解释争取。
2. Greasy Fork **会自动把 `@updateURL` / `@downloadURL` 改写为指向自己**，从市场安装的用户不会再去请求国内打不开的 `raw.githubusercontent.com`；GitHub 直装用户仍走原来的 raw，两边共存，脚本头一个字都不用改。
3. 支持从 URL 同步（含 GitHub webhook），每次推 GitHub 后市场自动更新，不用手动粘贴 220 KB。

## 三、发布步骤

1. 登录 <https://greasyfork.org/zh-CN>（支持 GitHub 账号）。社区反馈新账号约有 7 天反垃圾冷却期，若注册当天发不了脚本属正常；此条非官方规则，以实际提示为准。
2. 进「发布脚本 / 新建脚本」，**代码框整份粘贴** `AI-Web-Translation-Assistant.user.js`（含 `// ==UserScript==` 头部）。首次发布不要只填 URL——规则功能-4 要求主体代码在 GF 上。
3. 表单字段：

| 字段 | 填什么 |
| --- | --- |
| 名称 | AI 网页翻译助手 |
| 默认语言 | 简体中文 |
| 简介 | 复制 `@description:zh-CN` 那句 |
| 详细说明 | 第四节整段 Markdown |
| 标签 | 翻译、AI、效率工具 |
| 主页 / 源码 | `https://github.com/lengxiaobingege/AI-Web-Translation-Assistant` |
| 许可 | **留空**（不要选 MIT） |
| 脚本类型 | 公开脚本（不要选 library / unlisted） |
| 成人内容 | 否 |

4. 保存后核对 GF 页面显示的 `@version` 是 **1.4.18**、名称与双语描述正确，再从 GF 装一次，按 `Alt+N` 打开设置面板确认能出现。

## 四、可直接复制的脚本页正文

```markdown
# AI 网页翻译助手

任何网页，只要不是简体中文就自动翻成中文；F9 随时重译。只提供用户脚本这一种形态，装一个脚本管理器（篡改猴、脚本猫、暴力猴等）即可。

## 三层路径

本地界面词条 → AI 大模型 → 免费引擎链。前一层能解决就不花后一层的钱。

- **界面词条**：所有网站共用同一套词库，命中直接替换，零网络、零额度；自动排除代码块、文件名、路径。
- **AI 翻译**：按批交给你在设置里配置的大模型，译文缓存复用；不填 Key 也能用 `builtin`。
- **免费引擎链**：Bing → MyMemory → Google，AI 不可用、失败或文本超长时才兜底。

按 F9 翻译；页面已翻译时再按 F9 会先恢复原文再重译。打开设置面板：`Alt+N`，或在脚本管理器的菜单里点「AI 翻译设置」。无菜单的管理器（如 Safari Userscripts）请用快捷键。

## 数据与隐私

- 自动翻译默认开启，会把当前页面的可见文本发送给你选定的 AI 服务商，或 AI 不可用时发往 Bing / MyMemory / Google。这是整页翻译的实现方式，不收集用户身份、Cookie 或浏览历史。
- API Key 只保存在本机脚本管理器存储里，不写入任何远端；公开版内置 Key 为空。
- 词库同步是只读 GET（GitHub raw / 镜像），内容为纯 JSON 数据，不含可执行代码。
- 「词条回传」默认关闭，必须手动点按钮才会向仓库提交词条。
- 关掉设置里的「非简体中文页面自动翻译」后，只有按 F9 才会发起翻译请求；介意页面内容离开本机请勿安装。

## 脚本还会做的几件事

为避免「功能超出描述」，把全部对外行为列清楚：

- **菜单命令**：AI 翻译设置、立即更新词库、上传词库增量到 GitHub、提交词库 Issue、关闭翻译（恢复原文）。
- **词库同步**：每天 0 点后首次访问时，向 GitHub raw 与镜像并发 GET 一份 JSON，失败自动降级，离线时继续用本机缓存。
- **词条回传**（默认关闭）：手动点「上传词库增量到 GitHub」或「提交词库 Issue」时，会把页面上未命中的界面短句发到本项目仓库，需要你自己填 GitHub Token；不填 Token 时走预填 Issue 页面，由你确认后提交。发的是词条文本，不含 Cookie、身份或浏览记录。
- **更新检查**：由脚本管理器负责，脚本内部不自行检查更新，频率不会高于每天一次。

## 词库

正式词库是仓库里的 `dict/zh-CN.json`，所有网站共用同一份，不按站点区分。每天由仓库的定时任务续写、合并社区贡献并重新统计；脚本只读，不参与写入。

本脚本基于两个独立项目合并改编，二创新增内容包括三层调度、AI 批量翻译与缓存、全站共用词条库、三态存储适配、镜像降级、词条库维护流程与设置面板：

源码、完整文档与反馈：https://github.com/lengxiaobingege/AI-Web-Translation-Assistant
```

## 五、raw 地址、同步与自动更新

### `@updateURL` / `@downloadURL` 不用改

官方「元数据改写」页原文：

> `@updateURL` 和 `@downloadURL` 的数据会被添加或更新以指向 Greasy Fork。 `@installURL` 将被移除。

所以：

- 从 **Greasy Fork 安装**的用户：GF 已把这两行改写成自己的地址，用户浏览器不再碰 GitHub raw，国内网络不影响更新。
- 从 **GitHub raw 直接安装**的用户：读到的仍是原始两行，照常更新。
- **不要为了上架删掉这两行**，也不要改成 jsDelivr / gh-proxy——那会让所有非 GF 用户跟着走 CDN 缓存或第三方代理。这一条与之前脚本猫方案的结论一致，但 GF 有官方明文，不靠实测猜。

### 同步地址填哪条

首次发布后在脚本页的「同步 / Sync」设置里绑定外部 URL，这是 **Greasy Fork 服务器**去拉，用户浏览器不接触，所以官方 raw 直链可以用：

```text
https://raw.githubusercontent.com/lengxiaobingege/AI-Web-Translation-Assistant/main/AI-Web-Translation-Assistant.user.js
```

如果 GF 后台拉 raw 失败，再换这两条（本机实测 200）：

```text
https://cdn.jsdelivr.net/gh/lengxiaobingege/AI-Web-Translation-Assistant@main/AI-Web-Translation-Assistant.user.js
https://gh-proxy.com/https://raw.githubusercontent.com/lengxiaobingege/AI-Web-Translation-Assistant/main/AI-Web-Translation-Assistant.user.js
```

jsDelivr 有几小时缓存、gh-proxy 是第三方反代，**只在 raw 不通时才用**。不要填 `github.com/.../blob/main/...`（HTML 网页）或仓库主页。

### 三种同步方式

| 方式 | 做法 | 时效 |
| --- | --- | --- |
| 手动 | 脚本编辑页粘贴新代码保存 | 立即 |
| 自动（automatic） | 同步设置里填上面的 raw 地址，GF 定期拉取 | 约 24 小时 |
| Webhook | GF 用户页/脚本同步设置里拿到专属 Webhook URL → GitHub 仓库 Settings → Webhooks → Add webhook，Content type 选 `application/json`，事件选 `Just the push event` | push 后数十秒 |

推荐 **Webhook**：仓库每次推送即触发 GF 重新拉取，不用手动粘代码。同步类型名称来自 GF 发布表单（`automatic` / `manual` / `webhook`）与社区工具对表单的描述，界面措辞以实际页面为准。

**每次发版都必须递增 `@version`**，否则 GF 不会创建新版本，Webhook 触发了也白搭。

## 六、发布后

1. 拿到 `https://greasyfork.org/zh-CN/scripts/<编号>`，回填 README「发布地址」章节，并在安装章节把它列为国内用户的首选入口。
2. 从 GF 装一次，在管理面板点「检查更新」，确认请求的是 `greasyfork.org` 而不是 raw（按官方改写规则应当是前者）。
3. 之后每次发版：递增 `@version` → 推 GitHub → Webhook 自动同步；没配 Webhook 就到编辑页粘贴新代码。
4. **不要重复发布已被删除的脚本**：规则写明要用申诉功能，重发可能导致封号。

## 七、尚未消除的风险与待确认项

**版权（最重要）**：GF 规则文本比脚本猫站更严，写的是「必须遵守他人的版权…请遵守其授权规则或获得使用授权」；两个上游均无 LICENSE，按默认规则是「保留所有权利」。我们已在头部、README、描述页三处如实声明归属且不代授权，也有大量实质改进，但**严格讲并没有取得上游作者的再分发授权**。GF 与多数托管站一样以投诉驱动处理，短期发布一般不会被主动拦下；一旦原作者提出异议，脚本可能被删除。可选做法：

- 接受风险照常发布（当前方案，描述页已充分披露）；
- 先联系两位上游作者取得书面授权，再发布；
- 把词条数据与引擎链两部分重写为原创实现，只保留设计思路。

**其余待现场确认**：

- 发布表单的确切字段与同步设置入口位置（未登录状态看不到表单，上述名称按官方帮助页与社区工具描述整理）。
- GF 站内在国内的实际可达性未做实测；此前的镜像方案是为 GitHub 设计的，GF 若也不通，仍需保留 README 里的三个直装地址。
- 官方规则页**没有**针对 AI 生成脚本的专门条款，也**没有**强制 `@license`、强制 `@version` 格式；不要按别的站的规则自行加戏。
