# dict/contribs —— 用户回传的词库增量

这个目录存放用户回传的采集结果，是**待审核的候选条目**，不是正式词库。

## 两种来源

| 来源 | 文件 | 产生方式 |
| --- | --- | --- |
| 脚本推送 | `contrib-YYYYMMDD-HHMMSS.json` | 用户在面板填了 Token，脚本用 Contents API 直接写到 `main`（国内可经镜像） |
| Issue 接收 | `contrib-issue-<编号>.json` | 用户在面板点「提交 Issue」，维护者打上「词库贡献」标签后由工作流解析；维护者自己开的 Issue 无需打标 |

格式：

```json
{
  "schema": 1,
  "from": "userscript",
  "count": 12,
  "hits": { "zebra crossing ahead": "斑马线在前方" }
}
```

## 这些文件不是正式词库

正式词库是 `dict/zh-CN.json`。这里的文件**不会被脚本下载**，只作为待审核的候选条目。

## 合并方式

**自动**：每天北京时间 12:40 的「词库贡献合并」工作流会把队列并进正式词库，合并后删除已处理的贡献文件；lint 不过则整批回滚，不会污染正式词库。

**手动**（改错译、或想立刻生效）：

```bash
node tools/merge_contrib.js --dry     # 先看统计：新增 / 跳过 / 无效各多少
node tools/merge_contrib.js           # 只加不改：正式词库已有的键一律保留
node tools/merge_contrib.js --force   # 需要改错译时，用贡献值覆盖同名条目
```

合并提交后，用户脚本在每天北京时间 0 点后首次访问时同步到新词库。

## 审核要点

1. **术语一致性**：例如 pull request 统一「拉取请求」、fork 统一「复刻」，与正式词库冲突时保留正式写法。
2. **键是精确匹配**：按「小写 + 空白归一」比对，带变量插值的句子不要收，交给 `patterns` 或 AI。
3. **译文不要带英文**：`3 commits` 这类交给模式规则；纯数字、版本号、代码标识符不要收。
4. **空译文直接丢弃**，否则会把对应英文整段抹成空白。
